RollUp Visual Redesign & Onboarding Flow
Background
RollUp is a Blazor Server (ASP.NET Core 8) multi-tenant cafe management platform with Tailwind CSS v3.4, SignalR for real-time queue, and PostgreSQL. The codebase uses a CDN-served Tailwind config in _Layout.cshtml with "Cafe Espresso" tokens (cafe-espresso, cafe-mocha, cafe-caramel, cafe-cream). The compiled output is at wwwroot/css/app.css.

This plan covers:

Design token migration (CSS custom property–based accent, new fonts)
A 7-step onboarding wizard at /welcome → /register → /setup
A 5-destination authenticated shell (sidebar on desktop, bottom tab bar on mobile)
New shared UI components in Shared/UI/
A Menu → Design Studio sub-view within /menu
Runtime tenant branding via CSS custom properties
Bringing Queue, Menu Items, QR & Print, Insights, and Manage pages in line with reference prototype
Open Questions
IMPORTANT

Question 1 – Tailwind build pipeline: The app currently loads Tailwind via CDN in _Layout.cshtml with an inline tailwind.config. No tailwind.config.js file exists in the repo—package.json has tailwindcss@3.4 as a devDependency and the compiled app.css is already included via <link>. Should I switch to a proper build-time tailwind.config.js + JIT pipeline, or continue overriding the CDN config inline? A build pipeline is required for the new accent CSS custom property tokens to work correctly with JIT.

IMPORTANT

Question 2 – Tenant.HeadingFont / MenuLayout / CoverStyle fields: TenantBrandingDto has ThemeTemplate, ColorScheme, FontFamily, CustomPrimaryColor, CustomAccentColor. The spec asks for AccentColorHex, HeadingFont, MenuLayout, and CoverStyle on the Tenant entity and DTO. Do you want me to add these fields to Tenant.cs and TenantBrandingDto? This requires a new EF Core migration (adding 3 columns). I will flag and not proceed without your approval per the spec's rule.

IMPORTANT

Question 3 – Payment toggles in onboarding step 6: There is no PaymentMethod entity or table in the current schema. Should I store the selected payment method toggles (Cash / Card / Mobile wallet) on the existing Tenant entity as comma-separated flags, or flag this for you to decide the data model first?

CAUTION

Question 4 – Outlet type ("Food truck / Café / Kiosk / Restaurant"): No such field exists on Tenant or Outlet. Adding it requires a migration. Shall I add OutletType to Outlet.cs (enum + migration), or store it as a free-text string on the Tenant?

[MODIFY] 
Onboarding.razor → Setup.razor
Currently at /signup and /onboard with 3 steps. Rename file to Setup.razor with @page "/setup", @layout EmptyLayout. Replace with 7-step wizard sharing one component's state (no page reloads between steps). Steps, using WizardStep.razor shell:

Basics — Cafe/truck name (Tenant.Name), type selector (food truck / café / kiosk / restaurant — see Question 4 re: migration).
Branding — Template presets (Cafe Espresso / Street Bold / Clean Light mapping to bistro, minimal, artisan), accent swatch picker (sets Tenant.CustomAccentColor), live preview card (tiny phone frame using the accent CSS var in real-time via style attribute, no rebuild).
Outlet — Outlet name and address. Writes to Outlet.Name and Outlet.Address on the outlet already created during registration.
Categories — Chip row (Mains / Sides / Drinks / Sweets / Breakfast / Specials) + free-text add-own. Calls IMenuService to create selected categories.
Menu items — Compact add-item rows (name, price, category dropdown). "Skip for now" if empty. Creates MenuItem entities.
Payments — Three RollUpToggleSwitch toggles (see Question 3 on data model).
Review & Launch — Summary card per step with "Edit" links that jump back without losing later data. "Launch RollUp" → /setup/complete.
Complete screen (step 8 or route /setup/complete): congratulatory message with owner name, single "Go to Queue" button → /queue.

"Skip setup" escape hatch on every step: saves what's been filled so far, redirects to /queue.

NOTE

Wizard state is managed as C# fields on the single Setup.razor component (currentStep, wizardModel). No server round-trips between steps — data is only submitted on "Continue" actions that have side effects (categories, items) or on final "Launch".
